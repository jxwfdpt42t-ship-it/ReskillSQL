# 在线查询与后台学习：部署说明

当前新增的是可部署的**单机、单租户运行时**，不是已经上线的公网服务。完整启动命令、API、回滚和 Linux 配置见 [英文运行手册](DEPLOYMENT.md)。

## 三个核心改动

**持久化任务队列。** API 校验请求后立即入队，返回任务编号；查询 worker 与演化 worker 独立运行。SQLite 记录任务状态、尝试次数、租约和错误，服务重启不会丢掉已提交任务。重复请求使用同一幂等键返回原任务；键相同而内容不同则拒绝。租约过期后可重试，但旧 worker 的提交资格失效，不能覆盖新执行结果。

**版本发布。** 发布单位是 Skill、Memory 和配置清单的整体快照。先把文件完整写入并校验，再用一个数据库事务切换有效版本和完成任务。发布必须仍基于当前父版本；并行演化只有符合当前版本的结果能发布，其他结果标记 stale、保留证据。回滚也切换整个组合，并递增版本修订号，防止旧任务在回滚后误发布。

**并发隔离。** 每次尝试都有独立的工作目录、Skill 和可写 Memory。请求提交时固定发布版本，整个查询期间只读该版本；后台学习不修改线上正在读取的文件。每个任务在独立子进程中执行，worker 负责续租、超时停止和进程组清理。Linux 服务模板提供额外的内存和进程数限制。

## 学习与发布的顺序

```text
已核实的开发数据入队
  → 复制父版本到任务目录
  → 执行现有 Skill 演化与严格门禁
  → 本轮结束后，在私有副本中学习 Memory
  → 独立开发验收题比较最终组合与父版本
  → 租约、父版本都有效时，原子发布
```

研究命令原有的 weak_pass 行为保持兼容；部署入口改用严格门禁，存在退化的 Skill 候选不自动采用。Memory 学习之后还会对完整组合执行发布验收，不能只验证旧 Memory 下的 Skill，就直接发布新 Memory。

发布验收要求总正确数不下降且无旧对新错案例；允许持平，以便发布尚未造成验收退化的新经验。这是有限样本保护，不代表保证线上零退化。整体发布被拒绝时，经验仍保留在任务目录供复核，但不直接混入线上记忆。

## 数据与反馈边界

- 在线请求只允许选择注册的数据库别名，不接受任意数据库路径、gold SQL 或更新指令。
- 初始化会复制只读 SQLite 数据快照；当前不接入不断变化的业务主库。更换数据快照、模型或 Embedding 配置时需重新建立并验证运行时。
- 在线查询保存 SQL 尝试与发布版本，**不会因为执行成功就更新 Q**。
- 后台管理员提交 update、validation、release_checks 三份开发数据，必须有可靠参考 SQL 和稳定 source_id；release_checks 不进入记忆学习。
- release_checks 是生产版本选择用的额外开发验收集，不能冒充论文最终 holdout。最终测试集仍独立冻结，不能用于发布决策。
- 同一租户共享一个服务令牌；尚未提供多用户权限模型、人工标注平台、自动反馈审核或多机高可用。

## 启动与上线验收

安装 `serve` 可选依赖，初始化运行目录，再分别启动 API、查询 worker、演化 worker。Memory 需在初始化时启用并配置真实 Embedding 服务。所有运行数据默认放在被 Git 忽略的 `var/` 下；服务器建议使用私有 `/var/lib/reskill`。

提供了 `deploy/systemd/` 服务模板，可在 Linux 主机上使用专用账号托管和重启。API 默认绑定回环地址，公网访问需要 HTTPS 反向代理和速率限制。队列依赖本地 SQLite WAL，不支持跨机器共享或 NFS 挂载。

自动化测试覆盖了并发领取、过期 worker 拦截、发布事务异常、版本回滚、工作目录隔离、完整组合拒绝，以及通过本地模拟模型和 Embedding 服务运行的真实子进程查询与演化。目标服务器上的启动、TLS、备份恢复、实际模型连通性和容量压测仍需部署时验收；不能把这些测试写成已上线效果。

失败任务不会无限重试，默认最多执行两次。重复执行可能增加 API 费用，因此这是至少一次执行，不承诺模型调用恰好一次。保留旧版本和失败目录便于审计，暂不自动清理；运维应监控磁盘并在确认没有任务引用后维护数据。
